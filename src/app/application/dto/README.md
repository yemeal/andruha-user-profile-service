# Контракты данных прикладного слоя (DTO) (`user-profile-service`)

Модуль DTO прикладного слоя инкапсулирует строгие контракты входящих команд, запросов на чтение и исходящих моделей ответов по принципам **CQRS (Command-Query Responsibility Segregation)** и **Clean Architecture**.

Слой полностью изолирован от деталей транспортных протоколов и инфраструктуры: он не зависит от конкретных веб-фреймворков, баз данных или брокеров сообщений.

---

## 1. Базовые абстракции (`app.application.dto.base`)

* **`BaseDTO`** — корневая модель всех объектов передачи данных. Обеспечивает неизменяемость (`frozen=True`), поддержку псевдонимов (`populate_by_name=True`) и прозрачную гидратацию из доменных моделей (`from_attributes=True`).
* **`BaseCommand`** — базовый класс для всех команд мутации.
  * **Роль в системе:** Гарантирует строгую защиту от лишних/нерегламентированных параметров (`extra="forbid"`).
  * **Методы:** 
    * `non_none_fields(exclude=None)` — возвращает словарь только явно переданных полей (не `None`) для эффективных частичных обновлений (PATCH).
    * `to_dict()` — сериализация команды в плоский словарь.
* **`BaseQuery`** — базовый класс для запросов на чтение без побочных эффектов (`extra="forbid"`).
  * **Методы:** `to_params()` — сериализация параметров запроса.
* **`BaseResponse`** — базовая проекция данных для внешних потребителей.
  * **Методы:** `from_domain(entity)` — семантический фабричный конструктор из доменных агрегатов.

---

## 2. Команды (`app.application.dto.commands`)

Команды выражают **намерение изменить состояние системы** и содержат параметры для оптимистической блокировки (OCC):

### 2.1. Профиль (`dto.commands.profile`)
* **`CreateDefaultProfileCommand`**
  * **Роль:** Инициализация профиля со стандартным именем `Пользователь` и дефолтных настроек.
  * **Применение:** Вызывается при обработке событий регистрации и механизмом Lazy JIT Repair при первом входе. Содержит опциональный `event_id` для фиксации в Inbox-паттерне.
* **`UpdateProfileCommand`**
  * **Роль:** Изменение текстовых данных профиля (`display_name`, `bio`, `username`).
  * **Инварианты:** Защищён версией `expected_version >= 1` для предотвращения состояния гонки (OCC). Служит основой для No-Write оптимизации при неизменных данных.
* **`UpdateAvatarCommand`**
  * **Роль:** Установка нового ключа аватара в объектном хранилище либо его удаление при передаче `avatar_key=None`. Защищён версией `expected_version`.

### 2.2. Настройки (`dto.commands.settings`)
* **`UpdateSettingsCommand`**
  * **Роль:** Гранулярное обновление темы, языка интерфейса, часового пояса и политик приватности (`who_can_see_*`).
  * **Инварианты:** Защищён `expected_version` для OCC.
* **`ResetSettingsCommand`**
  * **Роль:** Явный сброс всех настроек интерфейса и приватности пользователя к системным значениям по умолчанию.

## 3. Запросы на чтение (`app.application.dto.queries`)

Запросы инкапсулируют параметры выборки и не создают побочных эффектов:

### 3.1. Профиль (`dto.queries.profile`)
* **`GetMyProfileQuery`**
  * **Роль:** Запрос собственного полного профиля авторизованного пользователя (`user_id`). Триггер для Lazy JIT Repair.
* **`GetPublicProfileQuery`**
  * **Роль:** Запрос публичной карточки пользователя с поддержкой `viewer_id` для динамической фильтрации приватных полей (свое vs чужое, а также задел под будущие связи Friends/Contacts).
* **`SearchByUsernameQuery`**
  * **Роль:** Поиск пользователя по уникальному никнейму (`username: 3..32 символа`) с учётом настроек видимости в поиске.
* **`GetBatchProfilesQuery`**
  * **Роль:** Пакетная загрузка публичных профилей (до 100 ID) для списков диалогов и чатов без проблемы N+1 запросов.
  * **Оптимизация:** Автоматически дедуплицирует идентификаторы с сохранением исходного порядка на C-уровне через `dict.fromkeys`.
* **`CheckProfileExistsQuery`**
  * **Роль:** Быстрая проверка существования профиля для внутренних межсервисных коммуникаций.

### 3.2. Настройки (`dto.queries.settings`)
* **`GetMySettingsQuery`**
  * **Роль:** Получение персональных настроек текущего пользователя для инициализации клиентского приложения.

---

## 4. Модели ответов (`app.application.dto.responses`)

DTO ответов гарантируют, что клиент получит только разрешённые данные без утечки внутренних полей:

* **`ProfileDTO`** — полное представление профиля для самого владельца. Включает статус жизненного цикла (`UserProfileStatus`), даты и версию для оптимистической блокировки.
* **`PublicProfileDTO`** — безопасное публичное представление для третьих лиц. Не содержит статусов аккаунта и дат. Поля `bio` и `avatar_key` маскируются в `None`, если целевой пользователь ограничил их видимость через `PrivacySettings`.
* **`SettingsDTO`** — полное представление настроек интерфейса, локализации и приватности.
